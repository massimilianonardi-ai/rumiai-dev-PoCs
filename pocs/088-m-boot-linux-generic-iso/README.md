# PoC 088 — M-02 generic Linux read-only ISO stage

**Scope:** isolated M-02 implementation and QEMU/OVMF test only. This does not implement M-03 original-init handoff or claim vendor installer support.

The guest-private `iso-stage.sh` reuses the **unchanged** C EFI Runtime Services/GPT map consumer from Ventoy branch `m-boot-secondary-uefi`, initially pinned to `ceff79ca92d246928f86362a569f86c6d2ac130f`, then tested against the revised F-owned consumer revision `f213b860982f540f43d51a296b05768d13587af2` without changing the producer ABI. It loads kernel modules, requires completed map validation before dmsetup, creates a read-only mapper, checks read-only kernel state, discovers its actual device from sysfs, and mounts ISO9660 read-only. Distinct error paths clean owned mapper and mount resources.

`guest-init.sh` is **only a test fixture**: it verifies the ISO marker and independently expected SHA256, tests fail-closed behavior on missing compiled map consumer, missing module manifest, absent/corrupt EFI runtime-variable bytes, missing dmsetup, unavailable disposable GPT whole-disk and partition nodes, duplicate valid primary GPT source GUID across two same-size virtual disks, guest device-mapper control-node denial, Linux dm-error target that returns EIO on real guest block I/O, corrupted ISO9660 metadata in a temporary QEMU snapshot, and last-step unbinding of the chosen disposable virtio-blk source from the guest kernel, then powers off. It does not pass control to any original OS init.

The dedicated workflow `poc-088-m-boot-linux-generic-iso.yml` reuses real PoC 081 EFI/QEMU execution and PoC 079's unchanged synthetic ISO/kernel with a disposable out-of-ISO initrd overlay. No operator USB, real disk, vendor install, GRUB core or Ventoy production branch is altered.

**Evidence:** genuine QEMU/OVMF guest mount PASS requires a completed successful workflow with kernel-side block-device read and independent hash. The guest negative cases exercise absent/malformed EFI-variable bytes through a guest-only tmpfs overlay, missing consumer/module manifest and dmsetup, missing disposable source disk/partition device nodes, and an invalid ISO9660 primary volume descriptor deliberately written **only to the disposable QEMU -snapshot view**, never the source file or host backing. The duplicate-GUID case writes and restores only a second disposable virtual GPT header under QEMU `-snapshot` and must observe the real C consumer refusing ambiguous source identity. The dm-error fixture submits a real Linux block read to a kernel device-mapper `error` target and checks that the generic stage refuses the resulting unmountable source with no lingering mapper. This **proves kernel EIO handling under a deliberately injected fault**, not a physical disk error or a failing QEMU storage backend. Hiding `/dev/mapper/control` proves ioctl access denial, not missing `dm_mod` kernel support. The final guest-only driver unbind test removes the exact disposable source virtio-blk device from the running kernel and checks the unchanged consumer refuses any fallback. It does **not** prove QEMU QMP hot-unplug, physical USB loss or absence of a kernel feature compiled into a different kernel at boot. These remain separate exact validation requirements; prior PoC 087 parser tests do not substitute for real guest tests.

The workflow preserves `m02-evidence.txt` alongside the actual QEMU serial log and the independently computed extent/hash oracle. The manifest identifies the PoCs and pinned Ventoy revisions, unchanged kernel/ISO SHA-256, guest module manifest, test outcomes and **untested** boundaries. It is generated only after all guest assertions succeed and is revision-specific.

The task finishes at generic M-02 read-only media exposure. M-03 and later work remain out of scope.
