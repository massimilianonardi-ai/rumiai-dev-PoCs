# PoC 088 — M-02 generic Linux read-only ISO stage

**Scope:** isolated M-02 implementation and QEMU/OVMF test only. This does not implement M-03 original-init handoff or claim vendor installer support.

The guest-private `iso-stage.sh` reuses the **unchanged** C EFI Runtime Services/GPT map consumer from Ventoy branch `m-boot-secondary-uefi`, initially pinned to `ceff79ca92d246928f86362a569f86c6d2ac130f`, then tested against the revised F-owned consumer revision `f213b860982f540f43d51a296b05768d13587af2` without changing the producer ABI. It loads kernel modules, requires completed map validation before dmsetup, creates a read-only mapper, checks read-only kernel state, discovers its actual device from sysfs, and mounts ISO9660 read-only. Distinct error paths clean owned mapper and mount resources.

`guest-init.sh` is **only a test fixture**: it verifies the ISO marker and independently expected SHA256, tests fail-closed behavior on missing compiled map consumer, missing module manifest, absent/corrupt EFI runtime-variable bytes, missing dmsetup, unavailable disposable GPT whole-disk and partition nodes, duplicate valid primary GPT source GUID across two same-size virtual disks, and corrupted ISO9660 metadata in a temporary QEMU snapshot, then powers off. It does not pass control to any original OS init.

The dedicated workflow `poc-088-m-boot-linux-generic-iso.yml` reuses real PoC 081 EFI/QEMU execution and PoC 079's unchanged synthetic ISO/kernel with a disposable out-of-ISO initrd overlay. No operator USB, real disk, vendor install, GRUB core or Ventoy production branch is altered.

**Evidence:** genuine QEMU/OVMF guest mount PASS requires a completed successful workflow with kernel-side block-device read and independent hash. The guest negative cases exercise absent/malformed EFI-variable bytes through a guest-only tmpfs overlay, missing consumer/module manifest and dmsetup, missing disposable source disk/partition device nodes, and an invalid ISO9660 primary volume descriptor deliberately written **only to the disposable QEMU -snapshot view**, never the source file or host backing. The duplicate-GUID case writes and restores only a second disposable virtual GPT header under QEMU `-snapshot` and must observe the real C consumer refusing ambiguous source identity. These tests do **not** prove hardware hot-unplug/media loss, missing kernel features or a genuine storage I/O error (EIO). These remain separate exact validation requirements; prior PoC 087 parser tests do not substitute for real guest tests.

The task finishes at generic M-02 read-only media exposure. M-03 and later work remain out of scope.
