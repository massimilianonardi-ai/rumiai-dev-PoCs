# PoC 095 — exact original Proxmox 9.2-1 GRUB config under F's virtual ISO data layout

**M-05 only — strict source-level test; not vendor boot/acceptance.**

This PoC retrieves the official Proxmox 9.2-1 `/boot/grub/grub.cfg` (and EFI first-stage config) by the already-tested PoC 082 **strict HTTP 206 Range** reader. It finds the **real unique ISO9660 directory records**, rather than substituting fixture offsets or trusting a remembered path, and checks the original image's logical length (1,706,178,560 bytes), PVD volume sector count, and actual GRUB file bytes.

An intentionally *uncommitted*, read-only, single-file virtual replacement is prepared with **the exact existing F-owned `vt_probe_set_overlay` data shape**: 8-byte PVD virtual-sector-count override at original byte offset `16*2048 + 80`, 16-byte directory-entry override at the actual source-record extent/size offset, and one appended, 2048-aligned config payload with a bounded **64 KiB** size. The original ISO is never copied or edited. Its vendor-published full SHA256 is NOT independently recomputed. This PoC does not modify or execute the F-owned C overlay producer.

The config transformation is intentionally minimal: only the **ten installer** `initrd /boot/initrd.img` lines receive a preceding fail-closed GRUB search for an **external sidecar** marker and a second `initrd` argument. Rescue-initrd commands and every other original line remain byte-identical; an exact before/after edit proof and `grub-script-check` are required. The `m05-probe.marker` and `m05-probe.cpio` names exist **only inside this private disposable PoC**; they do not define a product path, public configuration contract, EFI variable or API. The PoC does not claim these files are already available to the original vendor EFI GRUB — the source lookup, GRUB visibility, F actual selector, and original EFI boot must be demonstrated independently.

**Acceptance limit:** A PASS confirms the official vendor GRUB configuration is compatible *at the source/ISO9660 record geometry level* with an F-shaped bounded virtual-file shadow. It does not show the actual F-owned `vt_overlay_probe` selecting the vendor file (currently only synthetic `boot-hook` and `PAYLOAD.BIN;1` are supported), loading the original vendor bootloader, mapping physical FAT32 extents or accepting the original Proxmox CD ID. These remain M-05 BLOCKED and require explicit F/M coordination before altering F-owned experimental code.
